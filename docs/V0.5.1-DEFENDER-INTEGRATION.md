# Cortex Security v0.5.1 — Microsoft Defender Integration

## Scope
This increment adds an explicit Microsoft Defender custom-scan launcher and a report correlator. It does not disable Defender, alter its settings, quarantine files, kill processes, or claim that scan completion means every file is clean.

## 1. Run a scoped Defender scan
From the Cortex Security repository root, first scan a small directory:

```powershell
.\scripts\run_defender_scan.ps1 -Target .\scripts
```

PowerShell may require an elevated session for some Defender operations. Do not disable tamper protection or other antivirus products to make the command work.

The output `reports\defender-report.json` contains Defender status, the requested scan target, and available threat-detection history. Note: `Get-MpThreatDetection` can include older system-wide detections; it is not guaranteed to represent only the most recent scan.

## 2. Correlate with Cortex inventory
Run a filesystem scan for the same target:

```powershell
.\scripts\run_filesystem_scan.ps1 -Target .\scripts
```

Then correlate the two reports:

```powershell
python .\scripts\defender_integration.py `
  --filesystem-report .\reports\filesystem-scan.json `
  --defender-report .\reports\defender-report.json `
  --output .\reports\defender-correlation-report.json
```

The correlation report preserves detections and indicates whether a detected resource matched an inventoried path. A missing match does not invalidate a detection.

## 3. Verify
```powershell
python -m unittest discover -s tests -v
```

## Safety and limitations
- This is an explicit scan workflow, not continuous monitoring.
- Defender threat history may be incomplete or contain older incidents.
- Path matching is best-effort; aliases, device paths, and resource prefixes can prevent matches.
- The correlator is reporting-only. Continue using Defender's own UI/cmdlets for remediation.
- No automatic quarantine, process termination, or file deletion is implemented.
