# Cortex Security v0.4 — Unified Audit Reporting

## Run

From the repository root with `.venv-security` activated:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\run_external_audits.ps1
```

To audit a different requirements file:

```powershell
.\scripts\run_external_audits.ps1 -RequirementsFile requirements-security.txt
```

## Outputs

The runner regenerates these reports under `reports/`:

- `scan-report.json` and `scan-report.sarif` — Cortex heuristic scanner
- `bandit-report.json` and `bandit-report.sarif` — Bandit
- `pip-audit-report.json` — pip-audit for the selected requirements file
- `audit-run-status.json` — tool availability and exit status for this run
- `unified-audit-report.json` — normalized findings, source, status, severity counts, and scope
- `unified-audit-summary.md` — readable summary

The runner deletes only the listed previous generated report files before running, preventing stale reports from being mistaken for current results. It does not apply source or dependency fixes.

## Status semantics

- `passed`: the tool ran and returned no findings (for dependency audit, at least one dependency was represented)
- `findings`: one or more findings were normalized
- `inconclusive`: pip-audit produced a report with zero dependencies
- `not_run`: tool unavailable or check skipped
- `error`: the tool failed or its report could not be parsed

A zero-dependency pip-audit report is not evidence that packages are vulnerability-free. Audit scope is limited to the requirements file selected for that run. This workflow does not guarantee security.
