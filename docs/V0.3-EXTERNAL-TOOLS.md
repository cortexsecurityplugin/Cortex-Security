# Cortex Security v0.3 — external tool pilot

This pilot runs two established tools without integrating their findings into Cortex's own JSON/SARIF format yet:

- Bandit: Python static analysis. Official instructions: https://bandit.readthedocs.io/en/latest/start.html
- pip-audit: checks Python dependencies against published vulnerability advisories. Official project: https://github.com/pypa/pip-audit

## Install in an isolated environment (PowerShell)

From the repository root:

```powershell
python --version
python -m venv .venv-security
.\.venv-security\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-security.txt
```

If PowerShell blocks activation, you can invoke the environment's Python directly:
```powershell
.\.venv-security\Scripts\python.exe -m pip install -r requirements-security.txt
```
Bandit and pip-audit command entry points normally appear in `.venv-security\Scripts` after installation. If they are not found on PATH, activate the environment or call those executable paths directly.

## Run

```powershell
.\scripts\run_external_audits.ps1
```

Optional target and requirements file:
```powershell
.\scripts\run_external_audits.ps1 -Target "R:\path\to\authorized\repo" -RequirementsFile "requirements.txt"
```

Reports are written to the target's `reports` folder:
- `bandit-report.json`
- `bandit-report.sarif` (if the installed Bandit formatter supports it)
- `pip-audit-report.json`

## Safety and interpretation

- The script does not use `--fix` and does not edit application source or dependencies.
- `pip-audit -r` can resolve packages and contacts vulnerability services; use it only on repositories and dependency files you trust and are authorized to assess.
- Bandit is for Python code; it does not cover all languages or every vulnerability class.
- pip-audit checks known Python package vulnerabilities, not malicious packages or vulnerabilities in every native/system library.
- A nonzero exit may mean findings or an execution/configuration issue; inspect console output and reports.
- Do not commit reports if they contain sensitive paths or project details. Review the contents first.
