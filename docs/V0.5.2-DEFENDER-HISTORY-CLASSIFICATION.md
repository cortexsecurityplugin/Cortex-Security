# Cortex Security v0.5.2 — Defender History Classification

This patch corrects the reporting semantics of Defender integration.

- `Get-MpThreatDetection` may return system-wide historical records, not just the custom scan that was run.
- The report labels these as `historical_or_unattributed`.
- Exact duplicate records are removed using a stable fingerprint.
- `ActionSuccess` and `ThreatStatusID` are preserved but not interpreted as proof of current remediation.
- A path match to the filesystem inventory is reported as correlation, not as proof of current malware.
- `confirmed_current_threats` remains zero because this history export alone cannot establish current threat status.

Install the replacement `scripts/defender_integration.py` and add `tests/test_defender_integration_v052.py` to the existing repository, merging folders without deleting existing files.

Run:
```powershell
python -m unittest discover -s tests -v
python .\scripts\defender_integration.py `
  --filesystem-report .\reports\filesystem-scan.json `
  --defender-report .\reports\defender-report.json `
  --output .\reports\defender-correlation-report.json
```

Then inspect:
```powershell
$c = Get-Content .\reports\defender-correlation-report.json -Raw | ConvertFrom-Json
$c | Select-Object raw_history_records, unique_history_records,
    exact_duplicate_records_removed, records_matching_inventory,
    confirmed_current_threats, scan_attribution
```

This remains reporting-only. It does not remediate threats.
